FASE 5 — Correzione applicata: TOOLS-4.4 (adapter nuclei, fail-closed sull'output)

Difetto (correttezza / fail-closed). themis.adapters.nuclei.parse() scartava in silenzio ogni riga di stdout che non iniziasse con { (if not line.startswith("{"): continue). Ma nuclei è invocato con -jsonl -silent: stdout trasporta solo record JSONL. Una riga non-JSON lì è output inatteso — tipicamente un errore o un diagnostico (es. [ERR] rate limit exceeded; results truncated). Ignorandola, un errore stampato su stdout poteva passare inosservato e lasciar leggere il run come pulito (zero finding, nessun parziale) — violazione diretta del principio TOOLS-4.4: «né un errore sconosciuto diventi un esito pulito né un output innocuo diventi un falso fallimento».

Correzione. La riga non vuota che non inizia con { è ora conteggiata come record scartato (skipped += 1), esattamente come un record JSON malformato. coverage_loss() riporta i record scartati → partial (exit 5) con motivo esplicito; l'invariante preesistente (output senza alcun oggetto JSONL → ParseError → failed) è invariato. I diagnostici legittimi restano attesi su stderr. Nessun cambiamento alla superficie CLI.

# prima — una riga non-JSON su stdout veniva ignorata come rumore:
if not line.startswith("{"):
    continue
# dopo — è conteggiata come record scartato → il run diventa partial, mai pulito:
if not line.startswith("{"):
    skipped += 1
    continue

FASE 6 — Correzione applicata: TOOLS-4.4 (adapter nmap, stati canonici fail-closed)

Difetto (correttezza / fail-closed). themis.adapters.nmap.parse() parsava l'XML, iterava i <port> e restituiva i finding, ma non guardava il trailer di esito di nmap né lo stato dell'host. Conseguenze: (a) nmap può uscire 0 e dichiarare il fallimento nel suo trailer <runstats><finished exit="error" errormsg="…"> — ignorandolo, un errore diventava «zero porte aperte» = target pulito; (b) un XML valido ma non-<nmaprun> (strumento sbagliato sul PATH, documento d'errore) non aveva porte → stesso falso «clean»; (c) una scansione non conclusa o un host non scansionato (state != "up") producevano zero finding letti come target pulito. Violazione diretta di TOOLS-4.4.
