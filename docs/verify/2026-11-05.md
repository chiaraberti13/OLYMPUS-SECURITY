## FASE 3 — Review manuale delle superfici a rischio nuove

**API-4 — policy CORS/origin (`themis/api.py`): fail-closed, corretta.**
- `cors_allowed_origins` default `()` → **nessun header CORS emesso** senza allowlist esplicita.
- `_validate_cors_origin`: rifiuta il **wildcard `*`**, impone `scheme://host[:port]` esatto
  (regex: solo `http`/`https`, host DNS/IP, porta 1–65535; niente path/query/fragment/userinfo).
- Middleware aggiunto **solo** se l'allowlist è non vuota; `allow_origins` = lista esatta,
  `allow_credentials=True` **con origin espliciti** (pattern corretto — l'anti-pattern
  `*`+credentials è vietato), metodi `GET`/`POST` e header minimi. **Nessuna riflessione
  dell'Origin.** → nessuna vulnerabilità CORS.

**BLUE-2 — dispatch SIEM (`apollo/dispatch.py`): hardening SSRF robusto.**
- **Transport iniettato** (nessun client HTTP fornito; il `Protocol` vieta redirect/retry);
  i test offline iniettano un fake.
- `_validate_endpoint`: **https-only**, host/netloc obbligatori, **no credenziali in URL**,
  no query/fragment, no caratteri di controllo (`ord ≤ 32`/`127`), porta ≠ 0, e **path
  allowlist per provider** (Splunk `/services/collector/event`, Elastic `/_bulk`, Sentinel
  DCR/stream). `urlsplit` che fallisce → fail-closed.
- La destinazione deve passare il **callback `authorize_endpoint`** obbligatorio (scope
  egress dell'engagement firmato) + `policy.require_authorization` + `approval_reference`:
  l'host non è arbitrario ma **pre-approvato** (difesa anti-SSRF più forte di un filtro IP).
- Credenziale solo da `OLYMPUS_SIEM_*` (nome validato), **mai loggata**, CR/LF rifiutati
  (anti header-injection); bound su byte inviati (8 MB) e risposta (64 KB); batch vuoto
  rifiutato; validazione esito per-provider. → nessuna SSRF, nessun leak di segreti.
