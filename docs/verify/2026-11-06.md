## FASE 2 — Difetto corretto: TOOLS-4.4 (adapter httpx, fail-closed sull'output)

**Difetto (correttezza / fail-closed).** `HttpxAdapter.parse()` scartava in silenzio due classi
di output: (a) ogni riga di stdout che non iniziava con `{` (`if not line or not
line.startswith("{"): continue`) e (b) ogni record JSONL privo del campo `url`. Ma httpx è
invocato con `-json -silent -no-color`: stdout trasporta **solo** record JSONL del probe. Un
errore o un diagnostico stampato su stdout, o un record di grammatica inattesa, veniva perso →
il run poteva leggersi come **pulito** (zero finding, nessun parziale), violando il principio
TOOLS-4.4 «né un errore sconosciuto diventi un esito pulito».

**Correzione (regole verificabili, stati canonici).**

| Condizione nell'output httpx | Stato | Meccanismo |
| --- | --- | --- |
| Nessun record probe affatto (collisione col binario Python) | `failed` | `ParseError` (`_WRONG_TOOL`, invariato) |
| Riga JSONL malformata | `failed` | `ParseError` (invariato) |
| Riga non-JSON su stdout · record JSONL senza `url` | `partial` (exit 5) | nuovo conteggio `_skipped_records` → `coverage_loss` |
| Probe `failed:true` (host non raggiungibile) | esito legittimo, **non** scarto | `continue`, nessun parziale (invariato) |
| Probe valido, nessuno scarto | `clean`/`live` | invariato (nessun falso parziale) |

```python
# prima — una riga non-JSON su stdout spariva, come un record senza 'url':
if not line or not line.startswith("{"):
    continue
...
if not isinstance(entry, dict) or "url" not in entry:
    continue
# dopo — entrambi conteggiati come record scartati => il run diventa partial, mai pulito:
if not line.startswith("{"):
    skipped += 1
    continue
...
if not isinstance(entry, dict) or "url" not in entry:
    skipped += 1
    continue
```

**Verifica.** Ruff (`check` + `format`) ✅; mypy `--strict` ✅; Bandit sul file ✅ (0 issue);
pytest offline (`not container and not live_lab`) **3228 passed, 9 skipped, 0 failed**
(`PYTEST_RC=0`); drift gate tutti `current` (cli-reference, doc-links 77, schema 25,
engine-inventory, audit-exceptions). Regressioni in
`tests/unit/test_themis_adapters_projectdiscovery.py`: riga non-JSON su stdout → partial; record
non-probe → partial; probe pulito → nessun parziale; `failed:true` → nessun parziale; wrong-tool
→ `failed`; reset dello stato tra run.

## FASE 4 — Correzione applicata: TOOLS-4.4 (adapter non-mandatory, batch 1 — katana, dalfox)

Esteso lo stesso principio fail-closed ai primi due adapter **non**-mandatory, i più esposti a
output eterogeneo.

**katana** (`themis.adapters.katana`, crawler JSONL con `-jsonl -silent -no-color`). Scartava in
silenzio le righe non-JSON su stdout, i record non-dict e i record senza `endpoint`. Ora sono
conteggiati (`_skipped_records`) → `coverage_loss` → `partial` (exit 5). Invariati: output senza
alcun crawl record → `failed` (`"no crawl record"`); crawl vuoto legittimo → esito vuoto pulito.

**dalfox** (`themis.adapters.dalfox`, array JSON con `--format json`). Il quirk `[{}]` del target
pulito (un oggetto vuoto di padding) resta un esito **pulito** e non è mai conteggiato come scarto;
ogni altro elemento dell'array privo di `payload`, o non-oggetto, è ora conteggiato → `partial`.
Invariato: output privo di array JSON → `failed` (`"no JSON array"`).

| Output | katana | dalfox |
| --- | --- | --- |
| Nessun record utile affatto | `failed` (no crawl record) | `failed` (no JSON array) |
| Riga/elemento inatteso mescolato a record validi | `partial` (conteggio) | `partial` (conteggio) |
| Esito pulito | crawl vuoto → pulito | `[{}]` → pulito |

## FASE 5 — Correzione applicata: TOOLS-4.4 (adapter non-mandatory, batch 2 — wapiti, wafw00f, testssl)

Esteso il principio fail-closed a tre adapter non-mandatory a **report JSON**.

**wapiti** (report JSON): una categoria il cui valore non è una lista di finding, e un finding che
non è un oggetto, erano scartati in silenzio → ora conteggiati (`_skipped_records`) → `partial`.
Invariati: nessun JSON → `failed`; nessun oggetto `vulnerabilities` → `failed`.

**wafw00f** (array JSON): un root JSON che non è un array era letto come «nessun WAF» (clean) → ora
`failed` (`"root is not an array"`); un elemento non-oggetto è conteggiato → `partial`;
`detected:false` resta un esito legittimo (nessuno scarto).

**testssl** (array JSON): un root non-array → `failed`; le righe informative `OK`/`INFO`/`DEBUG`
(check superati) restano **rumore atteso** (ignorate, mai partial — verificato che il fixture reale
con `--severity LOW` contiene solo righe severity-bearing); una riga di errore o di livello
sconosciuto (es. `FATAL`, errore di scansione) è conteggiata come scartata → `partial`.

| Adapter | rumore atteso | errore noto / sconosciuto | esito pulito |

| wafw00f | — | root non-array → failed; elemento non-oggetto → partial | `detected:false` |
| testssl | `OK`/`INFO`/`DEBUG` | root non-array → failed; `FATAL`/sconosciuto → partial | solo righe informative |
