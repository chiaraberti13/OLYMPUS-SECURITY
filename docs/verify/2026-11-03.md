## FASE 6 — Test e correzione implementata

Prima esecuzione suite (venv in scratchpad di sessione): 7 fallimenti, **tutti
diagnosticati come artefatti d'ambiente**, non regressioni:

1. **6 test POSIX di isolamento processo** (`test_themis_sandbox_posix.py` ×5 +
   `test_themis_execution.py::test_runner_caps_output_sanitizes_environment_and_cancels`):
   `[Errno 13] Permission denied` nell'esecuzione dell'interprete della venv. Causa:
   la venv risiedeva in `/tmp/claude-0/...` (mode `0700` per isolamento di
   sessione), non attraversabile dall'utente non privilegiato a cui questi test
   fanno privilege-drop reale (`setuid`). **Dimostrato ambientale:** reinstallata
   la venv in posizione world-traversable (`/opt`) → tutti e 6 **passano**.

2. **`test_tui.py::test_closing_tui_stops_running_command_process_tree`**: fallimento
   **deterministico** (3/3). Riproduzione minima senza TUI/pytest: dopo che la TUI
   invia `killpg(SIGTERM→SIGKILL)` al process group del comando, il processo figlio
   risulta in stato **`Z` (zombie)** con `ppid=1`, e `PID 1` in questo container è
   `process_api` — **non** un init/subreaper che raccoglie gli orfani. La TUI
   uccide correttamente l'intero gruppo (il figlio *è* morto), ma la sonda di
   liveness `os.kill(pid, 0)` continua a rispondere positivamente sugli zombie,
   producendo un **falso negativo**. Il test gemello
   (`test_process_group_cancel_stops_parent_and_child`) passa perché il suo parent
   installa un handler `SIGTERM` che fa reaping del figlio.

### Correzione — `tests/unit/test_tui.py`

Aggiunto l'helper `_pid_is_terminated(pid)` che considera "terminato" un processo
**assente** *oppure* in stato zombie (`Z`, letto in modo robusto da
`/proc/<pid>/stat`). La sonda del test ora usa questo helper invece del solo
`os.kill(pid, 0)`. Un processo zombie è un processo già ucciso: la correzione
**non indebolisce** l'asserzione (il process group viene comunque terminato dalla
TUI), rimuove solo il falso negativo negli ambienti privi di subreaper; su sistemi
senza `/proc` (es. macOS) `PID 1` è un reaper e il ramo `ProcessLookupError` copre
già il caso. Verificato: 3 run isolati verdi + `test_tui.py` completo verde
(16 passed, 1 skip), Ruff pulito.

Nessun test disabilitato, nessun controllo soppresso, nessuna vulnerabilità
mascherata.

## Terza passata — 2026-11-03 ~11:30Z (correzione supply-chain: hint install engine)

**Intervento:** avanzamento del prossimo item P0 degli engine (`TOOLS-4`) correggendo
un difetto **supply-chain** confermato negli hint d'installazione degli adapter.

### Difetto individuato (DevSecOps + AppSec + Red team)

`ScannerAdapter.install` era una stringa scritta a mano, divergente dai manifest
pinnati, con due classi di problema operatore-facing (mostrate come "come installo
l'engine" quando una scansione non trova il binario):

1. **Riferimenti mobili `@latest`** in `nuclei`, `httpx` (entrambi **`mandatory`**),
   `katana`, `dalfox`: l'operatore avrebbe installato una versione arbitraria, non
   quella che la build verifica — esattamente l'anti-pattern che l'intero `TOOLS-4`
   vieta (nessun `latest`/tag mobile).
2. **Pacchetto errato** `pip install commix`: su PyPI `commix` è un pacchetto di
   terze parti (autore diverso), non `commixproject/commix` — rischio di
   **dependency-confusion** (lo schema lo documenta in `NOT_UPSTREAM_ON_PYPI`).
   Analogo rischio latente per gli `apt-get install nmap/nikto` ecc., incoerenti con
   la distribuzione `git` pinnata reale del manifest.

### Correzione (Technical Lead: sorgente unica)

- Nuovo `olympus.engines.loader.install_hint(name)`: ritorna il comando pinnato
  `EngineManifest.install_command()` (o `None` per engine `api`/senza manifest).
- `ScannerAdapter.install` è ora una **property** che deriva dal manifest via
  `install_hint(self.name)` (fallback `_install_fallback` solo senza manifest).
  Rimosse le 16 stringhe hardcoded negli adapter: l'hint non può più divergere dal
  pin. Catalogo `integrations/scanners.py` (superficie informativa separata, con
  contesto `(VAP_*_PATH)`/note) lasciato invariato — non nominato dalla ROADMAP.
- Risultato: `nuclei` → `…@v3.11.1`, `httpx` → `…@v1.11.0`, `commix` → install da
  `git` pinnato su commit, ecc. Zero `@latest`, zero pacchetti errati.

### Test e verifica

- Nuovo `tests/unit/test_engine_install_hints.py` (34 casi): per ogni adapter l'hint
  **uguaglia** `install_command()` del manifest e **non** contiene riferimenti mobili
  né `pip`/`go`/`gem` non pinnati; i 3 engine `mandatory` portano il pin esatto;
  `commix` punta a `commixproject/commix`, mai a `pip install commix`.
- Ruff + ruff format puliti; mypy `--strict` (233 file) verde; Bandit sui file
